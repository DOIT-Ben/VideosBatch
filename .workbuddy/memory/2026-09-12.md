## AUDIO_DELIVERY 接入 MiniMax T2A v2 语音合成（commit `b0bdf40`）

大哥给了 MiniMax 密钥（`sk-cp-` 前缀）要求把音频从 fake 换成真实 provider。

### 关键探测结论（免去猜参数）
- **`sk-cp-` 账户级凭据免 `GroupId`**：直接 POST `/v1/t2a_v2` 即 HTTP 200 返回 hex 音频。
- `GroupId` 是 **URL query 参数**（不是 body 字段），仅在显式配 `MINIMAX_GROUP_ID` 时附加。
- 端点 `https://api.minimaxi.com/v1/t2a_v2`，非流式单次返回，`output_format: "hex"` → `data.audio` 为 hex 字符串。
- `data` 可能为 `null`（status_code=0 时也如此），必须显式判定为空音频错误。
- 实测：4 秒窗口的文本合成出 **4.00 秒 / 32kHz mono mp3**，语速推算逻辑准确。

### 设计决策
- **TTS 独立开关** `VIDEOSBATCH_TTS_PROVIDER=fake|minimax`，与 `VIDEOSBATCH_MEDIA_MODE` 解耦。
  `tts=minimax + media=fake` 时只把 `AUDIO_DELIVERY` 单阶段覆盖到 native deps，视觉链路保持 fake
  （`createVideosBatchRuntimeStageRegistry` 的 else-if 分支）。
- **只有语音可插拔**：音效（`materializeSoundEffect`）与混音（`mixAudioTimeline`）保持本地——
  MiniMax T2A 是语音模型不产音效；各音轨已是本机文件，无需 provider 往返。
- 新增 `buildVideosBatchNativeMediaDeps(env)` 工厂，配置在 build 时一次性解析并闭包捕获。
- `AUDIO_DELIVERY` 产物 `provider` 字段改为按 deps 实际指向计算（`audioDeliveryProvider()`），
  能区分 `minimax-t2a-v2` 计费运行与 `videosbatch-fake-audio` 零成本运行。
- 计费安全：空文本 / 超长文本（>9000）本地拒绝不打 provider；合成 POST `idempotent: false`
  （超时和 5xx 不重放，避免重复计费）；文件内容寻址，相同文本+音色+参数复用不重复调用。
