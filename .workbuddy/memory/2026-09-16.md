  风控**（防「可能已花掉的钱被记成没花 → 系统再提交一次付费请求」），**不是**接支付、改价、
  动额度。碰过的文件无一是开关/凭据/额度文件。
- `runtimeProvider.ts`（模式唯一入口）最后一次改动为 `cc18dfc`（死代码清理），不在前两轮内。
- 当前运行时如实报 `executorMode=fake / mediaMode=fake / ttsProvider=fake`（`runtimeProvider.ts:74/79`
  的 `|| "fake"` 默认值，仓库原有约定，非人为设置）→ 零付费调用。真出片需双开
  `MEDIA_MODE=native` + `EXECUTOR_MODE=llm`，复用 SeeReel 凭据，切换前须用户点头。

## ADR-0001 第三轮执行：D3 + D9 落地（用户「全部授权。开始」）

### D3 参考图来源扩展（`3a5441b`，spec 1.4.7）

- `referenceCandidates()` 原先只放行 `^https://` 与 `/media/`，内联 `data:image/...;base64,...` 被
  **静默过滤**。现已三来源等价（HTTPS / `/media/` / 内联 `data:`）。
- 关键纪律：内联载荷**按 base64 长度预判 20MB**（在 `Buffer.from` 分配前拒绝）；复用同一
  `referenceBytes()` 保证内容寻址口径一致；提交地址改写为 `inline:sha256:<bytesSha256>`，
  **原始 data URL 既不保留在内存也不落库**。

### D9 付费执行快照完整性层（`5ca2235`，spec 1.4.8 / 新 §7.12）

- 新模块 `src/server/videosBatchWorkflow/executionSnapshotIntegrity.ts`：严格规范化 JSON
  （键递归排序、数组保序、`undefined`/非有限数字/非 JSON 值**硬失败**）、载荷 SHA-256、
  读取时重算 + 逐字规范形式校验、适配器能力矩阵闸
  （`(adapterKey, adapterVersion, runtimeModelId, creationMode, 参考图数量)`）。
- **⚠️ 刻意并存不替换**：`canonicalStoryboard.stableJson`（`JSON.stringify` 投影）**保留不动**——
  它服务血缘内容哈希，改它会重写全部已钉历史哈希。新模块只约束**付费快照**。这条边界
  写进了 ADR-0001 §13 与 spec §7.12。
- 接线：`onExecutionSnapshotPrepared` → `Shot.videosBatchExecutionSnapshot`；恢复任务先校验，
  适配器下架或载荷被改一律拒绝。适配器闸在**取参考图之前**执行。
- `executionSnapshotIntegrity.ts` 是叶子模块（只依赖 node:crypto），可被 shared 层安全引用。
