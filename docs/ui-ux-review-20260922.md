# VideosBatch UI/UX 优化与验收（2026-09-22）

依据：用户要求“前端体验这块给我深度优化一下吧，ui和ux这些”。本轮以 [UI System](../specs/ui-system.md) 为交互与视觉合同；工作流规则仍以 [canonical spec](../specs/videosbatch-workflow-canonical.md) 为准。起点为 `dde1097`。

## 实际观察与处理

| 观察 | 处理 | 用户可见结果 |
|---|---|---|
| 任务页重复标题、重复新建入口，大卡片难以比较，缺少检索 | 统一暖白/墨色任务列表，移除重复新建入口与标题，增加名称搜索、状态筛选、更新时间/名称排序 | 快速找到未完成、待确认或失败任务；空搜索可一键恢复 |
| 任务状态缺少进度依据 | 使用既有九步状态计算进度分段，显示当前步骤、状态与更新时间 | 不把已排队或未生成的任务展示为完成，不制造百分比 |
| “生成下一步”结果不明确，确认关卡仍有无效按钮 | 主按钮明确产物；确认/完成态使用说明，重试仅在可重试时出现 | 知道下一次点击的作用，并能回到当前制作步骤 |
| 重新生成与自动运行没有说明影响 | 共用 Radix AlertDialog 模式，明确重置范围/连续执行范围和真实生成费用可能性；默认焦点为取消 | 操作前可审阅后果，取消不发请求 |
| 运行期间浏览其他步骤，返回结果后强制切走 | 后台更新仅在用户仍跟随当前步骤时推进视图 | 保留正在查看的故事或草稿；运行状态仍明确可见 |
| 手机提示条 flex-basis 沿纵轴撑出 320px 空白 | 在窄屏恢复内容高度 | 内容更早进入首屏，不出现大片无意义留白 |
| 手机九个步骤挤窄、项目切换入口被隐藏 | 步骤保留可读宽度并横向滚动；选中/视口变化重新定位；恢复项目切换 | 可读、可切换项目，当前所看步骤保持可见 |
| 键盘读到英文状态，焦点反馈不足 | 中文状态名称、左右/Home/End 焦点导航、可见焦点环；编辑器行高与字号调整 | 可用键盘浏览步骤，不触发生成；长文编辑更清晰 |

## 验收证据

- `npm run build`：类型检查及生产构建通过。
- `npm run verify:offline`：隔离临时源码副本完整运行，RC=0；不复制真实 `.env` 或用户 data，API 使用临时数据/fake 服务。
- 最后追加的“异步返回不打断浏览”变更后，重新完成 build 和真实浏览器延迟请求验证；未重复无关后端测试。
- `smoke:videosbatch-task-experience`：搜索大小写/空白、分类、排序不改变输入、空结果、已完成动作与运行反馈；已纳入完整离线检查。
- `smoke:videosbatch-guided-studio-v2`、`smoke:videosbatch-product-ui-foundation`、`smoke:adr0003-workspace`、`smoke:specs` 通过。旧 guided-studio smoke 曾硬编码已经删除的变量/文案；本轮改为验证当前真实渲染的“待生成/生成中”差异，未放宽状态合同。
- Chrome headless 使用实际生产构建：390/768/1440px 截图复查、无页面级横向溢出；搜索空态/清除、状态筛选、名称排序、任务继续、确认关卡、键盘导航、弹窗默认取消及取消、故事草稿刷新恢复、延迟生成期间浏览后保持原步骤全部通过；未捕获 pageerror。
- 本地证据保留在 `.git/review-20260922/` 的 `ui-*` 截图与日志。真实 Provider、生产发布、完整画布编辑与所有九步的逐屏视觉审查不属于本轮已验证结论。

## 边界

本次调整任务发现和引导工作台，不改动生成服务、阶段顺序、资产确认规则、计费策略和草稿存储合同。继续保留 SeeReel 的导入、历史管理、作品广场和画布入口。生成验收使用 fake；UI 使用真实 Chrome。未部署生产。
