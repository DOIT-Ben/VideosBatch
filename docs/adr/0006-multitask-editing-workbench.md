# ADR-0006：多任务管理与编辑—保存—推进工作台

- 决策状态：PROPOSED；实施未开始；日期：2026-09-22。
- 原始需求：[U2 禁改](sources/20260922-automated-production-workspace.md#u2)、[U3 手感](sources/20260922-automated-production-workspace.md#u3)、[U4 编辑推进](sources/20260922-automated-production-workspace.md#u4)：“极致的体验和操作手感”“支持编辑保存，推进等”。
- 已确定：自动化生产工作台目标、报价禁改。交互细节以下均为 agent-proposed，尚未宣称用户逐项签字。
- 依赖 ADR-0004/0005；交付状态唯一见[阶段计划](automation-workspace-plan.md)。

## Context and Boundaries

当前已有任务搜索/筛选、九步工作台、sessionStorage 草稿、revision 冲突与生成期间不抢视图。`VideosBatchStudio.tsx` 467 行、`TaskList.tsx` 68 行、`useStageDraft.tsx` 45 行。现有保护继续保留，新增调度控件不可退回全局 busy 锁住所有项目。

本轮不做报价确认、价格/费用/积分展示、计费策略、支付管理；不改 FrameFlow；不顺便执行尚 Proposed 的 ADR-0002 提示词文档改造。九步与必要人工确认保持不变，管理看板不建立另一套创作阶段。

## Proposed Decision

### 1. 一个生产中心，两种工作视角

- 任务中心负责跨项目管理，项目工作台负责内容编辑；共享状态、过滤和运行身份，不创建复制项目的“第二条流水线”。
- 任务中心有全部／执行中／等待／待处理／已完成过滤；待处理汇总确认、版本冲突、失败、外部受理未知，点击直达具体项目/阶段/镜头。
- 每项只呈现标题、当前工作、明确状态、关键进度和适用动作；占用资源/排队原因按需展开。不展示内部状态码、worker lease 或原始 Provider 错误。
- 批量开始、暂停、继续、停止后续和重试失败项，执行前列出适用项及不适用原因。一个项目失败不撤销其他成功操作；返回逐项结果，重放仍幂等。
- 设置未开始任务优先级，解释“仅影响等待中的任务”；不承诺抢占模型。支持从任务列表逐个或多选启动已有项目；不把批量上传不同格式文件解析混入第一阶段。
- 管理视图的筛选/滚动位置保留；项目间切换保留所看步骤、展开块、光标和草稿；焦点不被后台进度抢走。项目上下文始终可辨认。

### 2. 编辑状态清楚，不让自动执行偷走输入

编辑状态明确区分：未修改、未保存、保存中、已保存、冲突、保存失败。sessionStorage 是断网缓存，不等于服务端保存；“已保存”须有服务端 revision 确认。

- 普通输入先保留本地草稿，不每次按键都发布正式 artifact 或触发后续重算。可增加服务端草稿层用于重开浏览器恢复，但它与正式版本分开存储。
- 编辑正式成果时登记可续期的编辑占用，暂缓相应节点尚未启动的自动动作；其他项目继续。占用断线失效后，曾有未提交编辑的分支停在待处理，不因租约过期直接使用旧内容推进。
- 占用须服务端确认后才显示“已暂缓自动推进”。若派单先发生或正在离线，仍允许准备本地草稿，但明确在途工作使用旧版本；不能声称一次本地按键已阻止服务器执行。多标签占用不能由另一标签关闭编辑直接清除。
- 已运行任务使用冻结输入；新编辑保存为新版本。旧请求完成只更新其版本，不能覆盖新稿或把旧结果接到新版本下游。
- 保存携带 expectedRevision、draftId、requestId；返回后仅清理本次提交且未继续改动的草稿。保存期间继续输入、切项目、重新挂载都不丢新内容。
- 冲突保留“我的草稿”和“服务器新版”，允许对照、复制、重新基于新版编辑；禁止默认最后写入者获胜。自动合并只用于可证明互不冲突的字段，否则显式选择。
- 保存失败保留输入和重试入口；离线时明确“仅保存在本机”，不显示伪成功。服务端草稿按 owner/session 隔离，删除项目沿用现有删除合同，不新增批量销毁功能。

### 3. 保存与推进是两个明确动作

- “保存”只发布内容版本；显示受影响下游范围，不默认启动新的生成。
- “保存并继续”先验证并保存，再以该精确 revision 入队。控制记录持久化推进意图，投影完成后才激活；任一步失败可恢复，重复点击不重复生成。
- 若保存成功但入队失败，明确显示“已保存，尚未开始”并提供继续按钮；重试只补入队，不能再次无意义增版本。
- 人工关卡使用“确认并继续”，服务端验证确认内容和 revision 后推进，不能仅因为用户关掉弹窗就视为确认。
- 自动模式停在待确认/冲突/不可自动恢复错误；确认后接回原计划。修改导致失效时保留旧成果，只重算受影响部分；不默认清空整个项目。
- 单镜头修改/保存/重做与多镜头选择共享同一稳定 sequence、revision 和运行记录；成功项复用，依赖镜头按实际依赖等待。未选镜头不会悄悄提交。

### 4. 操作反馈与可访问性

- 点击后立即进入请求中，但后台确认前不说“已暂停/已保存”；控制按钮只锁当前命令，不锁整页和其他项目。
- 高频进度不弹 toast、不跳页、不自动更改所选任务。单一可见待处理入口避免重复红点；终态通知可聚合。
- 自动执行中仍可查看和准备草稿；冲突范围内编辑明确提示当前运行使用哪一版。即使在后台任务很多时，搜索和键盘输入保持响应。
- 支持键盘浏览任务和步骤，编辑器内 Ctrl/Cmd+S 保存；焦点在编辑器外不接管无关快捷键。保存成功不挪光标，弹窗关闭还焦，reduced-motion 生效。
- 移动端可以查状态、确认和基础编辑；桌面优先承载密集批量管理，不用把全部列硬挤到手机。沿用 390/768/1440px 验收。

## Module Boundaries and Alternatives

新增 `productionCenter/`（列表、过滤、批量动作与待处理投影）、编辑状态 hook/草稿 API 适配器；不把所有事件和表单状态塞进 App。既有 StageWorkspace 继续负责阶段内容，编排控制与编辑提交协调分开。

仅 sessionStorage：保留作离线缓存，但不能承诺关标签/换设备恢复；仅服务端自动保存：断网输入及自动发布风险高；推荐本地即时草稿 + 服务端草稿 + 显式发布三层，但区分状态和版本。

复制一个“自动化页面”：短期快，长期形成两套状态和操作口径，拒绝。优先增强当前任务页与工作台，避免用户在两套产品间跳转。

## Compatibility and Rollback

旧草稿键保留并按 schemaVersion 可逆读取；迁移不能静默删本地草稿。关闭新看板后仍可通过已有工作台访问项目和运行记录；新任务不能因视图回退而丢失控制入口。报价相关范围、生产发布和真实 Provider 调用均不由本 ADR 自动授权。
