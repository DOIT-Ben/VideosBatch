# ADR-0005：实时状态、渐进内容渲染与低干扰反馈

- 决策状态：ACCEPTED；实施状态见阶段计划；日期：2026-09-22。
- 原始需求：[U3 自动化](sources/20260922-automated-production-workspace.md#u3)、[U4 实时](sources/20260922-automated-production-workspace.md#u4)：“实时渲染和反馈”；[U2 禁改](sources/20260922-automated-production-workspace.md#u2)适用。目标已确定，以下协议和指标为 agent-proposed。
- 依赖：[ADR-0004](0004-durable-production-scheduler.md) 的持久运行与事件；交付状态见[阶段计划](automation-workspace-plan.md)。

## Context

现有 `App.tsx` 2591 行承载全局状态，5 秒 ETag 轮询已避免无变化传输并复用对象；镜头另有轮询。不是所有情况都全量下载，但工作流缺少持续事件与可恢复游标。现有 StageExecutionContext 只有阶段 checkpoint，不能凭空显示 Provider 实时 token 或精确进度。

FrameFlow 的运行事件续接是参考，原始模型 JSON 不应直接倒入用户编辑器。实时目标同时包含“点击即反馈、过程可理解、成果逐步出现、页面不抖动”，而不只是增加一个 WebSocket。

## Proposed Decision

### 事件与同步

- 优先同源 SSE：一个页面一条 owner 范围多任务事件连接，认证沿用现有会话；不为每个镜头单独建连接。Socket 与 SSE 不双写同一状态。
- 事件包含 eventId/sequence、runId、itemId、输入/输出 revision、类型、时间、安全摘要；只传变更和成果引用，不传全 store、密钥或 Provider 原始诊断。事件从已提交台账读取，不能先推送后落盘。
- 初始快照携带一致的 high-water cursor，再续接后续事件，覆盖快照与订阅之间的竞态；客户端去重、拒绝旧版本、检测缺口。事件过期返回 resync 指示与新快照游标；游标不是访问凭证。
- sequence 采用同一 owner 事件流内连续序列，项目过滤发生在客户端投影层；不能把其他 owner 的事件被过滤形成的序号间隙误判为丢包。若改用服务端子集订阅，必须另定义该子集的连续游标合同。
- 断线指数退避加抖动，重连不创建新任务；显示“连接恢复中，后台任务继续执行”。心跳不等同生成进度。退回有界轮询而非重复启动执行。
- 隐藏标签页降低绘制频率，不停止后台任务；返回后补快照/游标。多个标签页各自可恢复，首次不依赖复杂跨标签 leader election。
- 旧 ETag 轮询作灰度兜底；切换由一个同步协调器决定，禁止事件和高频全局轮询同时反复更新同一状态。

### 内容实时呈现

- 三层明确区分：执行状态、临时预览、已保存成果。排队/等待 Provider/校验/保存均来自真实执行边界，不编造百分比或完成时间。
- 文本流只有适配器确实支持时才提供。可独立校验的完整段落/镜头块可逐步预览，标“生成中，尚未保存”；结构化 JSON 的不完整片段不渲染成正式成果，不进行全量反复 repair 以制造实时感。
- 不支持流式结果的 Provider 显示真实状态、已完成项和经过时间，不用打字机动画假装模型正在输出。
- 草稿和正式成果不被预览流覆盖；校验通过且持久化成功才切换为可继续使用的结果。失败保留已验证部分和明确原因，不把半成品标 ready。
- 用户停留底部且未编辑时才跟随追加内容；上翻后停止追尾并显示“有新内容”。新块不重挂载旧块，滚动锚点和已展开内容保持。

### 渲染和反馈成本

- 新增 run store/selectors、event reducer、useRunEvents 与独立反馈组件，App 只接线。按任务/项/revision 局部更新，稳定 key；避免 token 到来就重算全部 Markdown 或重新拉整个会话。
- 状态批量在一帧内合并；终态、错误和保存确认不被节流丢失。列表达到实测阈值后再窗口化；编辑中的行、焦点、展开块必须保留，不为虚拟化牺牲输入。
- 即时本地反馈表示“请求发送中”；服务端持久接收后才显示“已加入队列”。保存、暂停和取消也区分请求中与已确认。
- 普通过程内联呈现；需要操作的异常进入待处理中心；不为每个镜头成功弹 toast。aria-live 使用 polite，终态及异常按需要提升，禁止每 token 播报。
- 动画遵守 reduced-motion，不以持续动画制造虚假活跃；内容尺寸有占位，完成时不大幅跳动。

### 性能目标（待测，不是已达到的结果）

记录浏览器版本、机器 CPU/内存、视口、网络条件、冷/热启动和样本数。固定合成集：1000 个项目摘要、5 个活跃项目、合计 60 个镜头、当前页 2 万字；10 events/s 持续 60 秒并含 100 events/s 短突发。每类交互至少 30 次，端到端与前端时间分开报告。

- 点击/输入到可见本地反馈 p95 ≤ 100ms；不得阻塞输入等待网络。
- 浏览器收到状态事件到绘制 p95 ≤ 250ms；应用状态节流不超过该目标。
- 已缓存项目切换到可操作 p95 ≤ 300ms；未缓存先显示可访问加载态，并单独测网络耗时。
- 自动流水线单项完成到后继入队，在无关卡/限额阻塞的隔离环境 p95 ≤ 1s。
- 不允许单个界面更新造成 >200ms 的主线程长任务；记录 >50ms 长任务分布和最差帧。未达标定位后修复，不通过缩小测试数据量掩盖。

若目标不适合实际设备，提供原始测量与权衡，再修订目标；不得先修改断言使其通过。真实模型首字时间与生成总耗时另测，不能用 fake 测试冒充。

## Alternatives, Compatibility and Rollback

仅缩短轮询间隔易增加请求和重绘，保留作兜底而非主方案；Socket 可双向但当前控制动作已有 HTTP API，首选 SSE 降低复杂度。事件失效可降级到快照模式；用户草稿与执行台账不因切换同步模式而改变。更新不得成为另一个业务状态真源。性能与浏览器验收计划见阶段计划，生产网络代理缓冲/断线单独验收。

### P3协议细化（2026-09-22）

沿用本文允许的服务端子集订阅合同：本机共享/管理员可见多owner时，以单连接承载owner游标向量；每包previous/cursor承认服务端过滤跨度，授权session集合摘要变化强制快照。普通owner仍使用独立连续序列。每owner保留最新10000事件；首次快照及游标同步读取；过期游标回快照。完整合同见specs/ui-system.md；不暴露其他owner载荷，也不把过滤导致的跨度当丢包。
