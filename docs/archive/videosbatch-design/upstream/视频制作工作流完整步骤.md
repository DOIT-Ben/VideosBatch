> 执行边界：十秒创作分镜是用户审核单元。当前 Provider 采用一对一十秒执行片段映射，不自动合并或拆分；可复制文本只是展示副本，结构化分镜和稳定资产编号才是执行真源。

> 时长冻结：当前新链路只允许 `90/100/110/120/130/140/150` 秒。未指定时长时，界面和模型可以把 `120 秒`作为默认建议，但它不是额外规则，也不能放宽或改变上述允许集合。故事文稿阶段不锁定时长；正式视频剧本使用 `targetDurationSeconds` 锁定目标时长，最终分镜使用等价的 10 秒主分镜数量完成校验。历史成果中的其他时长只用于读取兼容，不得作为新链路输入或新成果输出。

> 结构化调用边界（2026-08-27）：视频创作页面的每个生成阶段都由专用服务端 Runner 直接调用云端文本模型，默认模型为 `gpt-5.6-terra`，不经过通用 Chat Agent、工具提案或对话 finalizer。每个阶段发送阶段专用 `json_schema`，不支持 Structured Outputs 时明确失败，不静默降级为 `json_object`。一次用户点击对应一次正常模型请求；Schema/业务合同、截断或拒答最多三次总尝试，禁止隐藏 finalizer 或 repair 生成。结果未知、权限、版本冲突和资产归属错误不自动重试。模型返回后先由服务端解析、规范化、权限/版本校验和阶段转换，再生成用户可读成果投影。

> 交付边界：服务端通过持久化运行事件向视频页面推送 `run_started`、`stage_changed`、`progress`、`artifact_ready`、`error` 和 `done`；不把模型原始增量作为内容流展示。页面只展示阶段状态、耗时、尝试次数、安全诊断和服务端投影后的成果。下一阶段的输入由服务端从当前确认版本显式组装，不依赖聊天历史上下文。

> 用户主导输入边界（2026-08-27）：模型生成结果是内部结构化建议稿，服务端先将其投影为用户可读成果。页面不展示原始 JSON 或内容增量；用户可在成果级界面查看、编辑、保存并选定课程导入卡片、故事、资产、剧本和分镜。确认后的版本才作为下一阶段输入；外层结构保持合法，文本内容可自由修改。格式诊断只用于提示和重试，不阻塞草稿保存。服务端仍强制校验用户/项目归属、来源版本未过期、内容非空、确认状态和最终执行所需的 90–150 秒及 10 秒分镜等底线；自定义课程导入使用 `selectedIntroId: CUSTOM`，仍保留教案来源和版本血缘。

> 工作台展示边界（2026-08-27）：视频项目页采用紧凑阶段栏和“阶段索引 / 当前成果 / 操作与详情”三栏。中栏一次只投影当前来源子步骤、资产类别、剧本场次、分镜或执行片段；长编辑、候选确认和预览按需在右栏、抽屉或对话框打开。窄屏优先展示当前成果，索引和操作改为可关闭抽屉。切换视图只改变本地 UI 选择，不改变成果版本、确认状态、计费或模型调用。

> 运行合同（阶段一，2026-08-26）：视频阶段运行使用 `VideoCreationRun` 和 `VideoCreationRunEvent` 保存项目/用户归属、幂等键、来源版本与内容哈希、部分正文、租约和安全事件。公开接口为创建运行、读取运行、按 `Last-Event-ID` 读取事件、取消和显式重试；所有错误统一返回 `{ error: { code, message, retryable } }`。终态必须有可验证的成果或安全失败信息：没有 `artifact_ready` 成果不得写入 `COMPLETED`，没有安全错误码和文案不得写入 `FAILED`/`CONTRACT_INVALID`。该运行合同已落地。
>
> 阶段二、三（2026-08-26，历史状态）：专用 Runner 和项目页曾使用 `deepseek-v4-flash` 并展示流式正文。该描述已被 2026-08-27 的 Terra 结构化成果规则取代。
> 当前状态（2026-08-27）：六个视频阶段由专用 Runner 使用 `gpt-5.6-terra` 的 Responses API 和阶段专用 `json_schema`，禁用工具、Agent 路由和隐藏 finalizer。模型返回先在服务端解析、规范化并投影为成果级 UI；页面只展示安全状态和可编辑成果，不展示原始 JSON 或内容增量。用户保存并确认后的版本才进入下一阶段；结构化失败最多三次显式总尝试，失败草稿可编辑确认。真实浏览器和真实 Provider 证据仍由用户验收，不在此处伪造为已完成。

> 运行观测（2026-08-26）：视频 Runner 记录 `video_creation_run_started`、`video_creation_provider_observed`、`video_creation_run_terminal` 三类安全事件，区分 Worker 领取、Provider 首事件、首个正文和终态耗时；图片/视频 Generation 记录提交、重试、未知提交对账和终态状态。日志不包含正文、提示词、Provider 地址、Token 或原始响应。

## 1 第一步：根据教案生成三类九套课程导入

【教案内容】

{{教案}}


以上是本课教案。请根据这份教案，完成下面的任务。


你是一名小学数学课堂趣味导入创意策划专家，擅长把数学知识的由来、历史需求、古今应用和生活问题转化成适合小学生理解、可继续扩写为故事文稿的课程导入。正式视频剧本的目标时长在后续阶段统一锁定为 `90–150 秒` 的 10 秒整数倍。


请依据上述教案材料，为本课生成三类九套课程导入。识别各材料的用途与衔接关系；若缺少完成本步骤所必需的信息，请直接列出缺失项，不要自行改变课题、核心目标或教学范围。


九套方案应尽量覆盖以下不同方向，避免同类方案只是更换人物或地点：


A. 数学史与知识由来：

\- A1：知识产生所要解决的原始问题；

\- A2：可靠的数学史人物、事件或真实时代背景；

\- A3：方法、工具或表示方式的形成与演变。


B. 历史需求与古今应用：

\- B1：古代生产或生活中的真实需求；

\- B2：同一问题在古代与现代的解决方式对照；

\- B3：现代生活、工程、科技或公共服务中的真实应用。


C. 创意故事与现代情境：

\- C1：学生熟悉的生活冲突或错误现场；

\- C2：推理、游戏、挑战或任务情境；

\- C3：科技现象、自然现象或具有画面感的异常情境。


若某个子方向与本课没有可靠联系，可以在同一大类中更换为更合适的方向，但九套方案必须在冲突来源、推进方式和画面场景上明显不同。


生成前必须先完成以下判断，但不要单独输出分析过程：

1. 准确判断本课核心数学知识点、它解决的真实问题以及适合嵌入故事的位置；
2. 判断哪些数学史、知识由来、历史生活需求或古今应用与课题存在可靠联系；
3. 找出最适合制造问题、冲突、误会或悬念的位置；
4. 明确本课尚未学习、不能在导入中提前讲透的概念、方法、性质、公式或规律；
5. 检查故事语言是否符合对应年级，情节能否通过清楚的画面、动作和少量人物表现；
6. 检查九套课程导入的开头、冲突来源、推进方式、场景和结尾是否真正不同。


方向优先级：

1. 优先使用数学历史人物、数学知识由来、历史事件、古代真实生活需求和知识点古今应用；
2. 数学史素材不足或无法确认时，不得硬编真实人物或真实事件，可改用明确的虚构古代人物、古代生活情境或传统生产生活场景；
3. 创意故事与现代情境可从生活问题、科技应用、悬疑推理、错误现场、游戏挑战、自然现象等方向切入，但必须服务于本课数学知识，不能只追求热闹。


核心质量要求：

1. 每套课程导入都要让人一眼看出故事画面、核心冲突和数学价值；
2. 本课知识点必须是解决故事冲突的关键线索，不能在故事末尾生硬点题；
3. 开头直接出现人物需求、异常现象、争议或待解决的问题，不使用"今天我们来学习……"等传统讲课开场；
4. 结尾只留下学生想知道"为什么、怎么算、怎么量、怎么分、怎样比较或怎样解决"的问题，不给答案；
5. 不得提前解释本课核心结论，不得增加教材之外需要学生掌握的数学知识、方法、例题、练习或结论；真实背景和故事情境只用于提出问题；
6. 九套课程导入不能只是更换标题、人物或地点，也不得反复使用同一种穿越、神秘任务、系统故障、打不开门、算不出来等套路；
7. 内容适合对应年级，人物和场景从简，能够转化成视频，避免复杂群像、宏大战争场面和难以稳定生成的连续动作；
8. 本步骤只生成200—300字课程导入，不扩写600—800字故事文稿，不写正式视频剧本、分镜、旁白、字幕或图片资产建议。


真实性规则：

1. 使用真实历史人物或事件时，只能以公认事实为背景；对话、场景和心理活动可以合理文学化，但不得编造不存在的重大发明、作品、身份、经历或成就；
2. 无法确认某位人物与知识点存在直接关系时，不得写成"某某发明了它"，应改为"人们在解决某类问题时逐渐发现或使用了这种方法"；
3. 使用虚构人物或情节时，必须在真实性说明中明确标注，不得伪装成真实历史。


每套固定按照以下格式输出：


课程导入编号与名称：

创意类型：

课程导入正文：

结尾悬问：

真实性说明：


其中，"课程导入正文"必须控制在200—300字，字数不包含课程导入名称、创意类型、结尾悬问和真实性说明。正文应连贯写清：

\- 故事发生在什么情境；

\- 谁遇到了什么问题；

\- 冲突如何出现或升级；

\- 本课知识为什么会成为解决问题的关键；

\- 故事最终停在什么待解决的位置。


"真实性说明"只能根据实际情况标注为以下三类之一，并用一句话说明依据：

\- 真实史实；

\- 真实背景下的合理改编；

\- 完全虚构的故事化情境。


九套课程导入完成后，推荐最值得继续制作的3套。每套推荐理由控制在80字以内，分别说明其课堂吸引力、与核心知识点的连接强度和视频制作可行性。

九套方案只是候选集合。用户可以直接选择其中一套，也可以确认系统推荐的一套；确认后必须锁定唯一方案，后续故事文稿、资产计划、正式剧本和分镜都只能围绕这套方案继续，不得并行扩写或混用其他方案。


请严格按照上述要求输出，不要遗漏任何一套课程导入，也不要输出多余分析内容。

景别安排：单个10秒分镜内设置1处特写，聚焦算盘珠、账本数字、地图线路、尺规刻度、古籍文字、人物表情等。

运镜设计：常用慢速横移、局部推近、画卷展开、时间轴滑动、古今叠化、地图路径生长。

精炼音效：单条音效字数控制在十字以内，固定格式：音效：XXXX；音效贴合时代和课堂氛围，避免压迫和惊吓。

讲解特效：可添加关键词浮现、地图箭头动效、时间轴节点闪烁、数字高亮、正误对照、古今画面分屏等，辅助观点输出，简洁不炫目。

旁白情绪：每份分镜配置1-2句讲解型旁白，情绪亲切、有画面感，避免成人化、纪录片腔过重。

真实性要求：涉及真实人物、历史事件、数学史和传统文化时，必须保持基本准确；不确定的内容不要说成确定事实，可使用“人们曾经”“古代生活中常见”等稳妥表达。
