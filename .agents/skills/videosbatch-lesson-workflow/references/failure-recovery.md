# 失败与恢复

先读取当前运行目录的 `run_manifest.json`、`worker_jobs.json` 和事件记录，再决定恢复动作；远程适配才读取 `/videosbatch` 状态。不要手写状态 JSON，不要用同样的输入盲目重复提交。

## 分类

| 情况 | 处理 |
| --- | --- |
| 输入缺失或解析失败 | 保留原输入和错误，修复输入后从 `LESSON_INPUT` 重新开始 |
| 结构或业务校验失败 | 保留失败产物和错误，按 canonical spec 的修复预算或显式重试 |
| 来源 revision/hash 不匹配 | 标记为过期，回到当前上游，不使用旧产物 |
| 单个资产或镜头失败 | 只隔离当前项，保留其他成功项 |
| `pending` / `running` | 读取状态或等待，不重复创建任务 |
| 未知 Provider 提交 | 先对账任务状态，禁止盲目再次扣费 |
| 音频未就绪 | 不创建成功的拼接任务；有语音/音效事件时补齐对应 URL 和 mix 后再重试；没有待播语音事件时 `tts=[]` 合法，但 mix 仍必须 ready |
| 真实媒体或报价动作 | 停止并请求本次用户明确授权 |
| Worker 局部失败 | 保留成功单元和失败证据，只重试失败单元；不得用空值覆盖成功结果 |

## 重试前检查

1. 阶段必须仍是 `failed`，且服务端标记为可重试。
2. 所有依赖阶段必须是当前 `ready`，来源 revision/hash 必须匹配。
3. 将当前来源 revision/hash 传给重试 API。
4. 重试后重新读取状态，记录新的 attempt 和错误，不覆盖历史证据。

并发 Worker 重试前还要确认：单元仍属于当前计划、没有重复的 running 租约、幂等键未被已提交任务占用；无法确认提交状态时先对账，不重新扣费。

## 不允许的恢复

- 不把 `PARTIAL`、空 URL、未完成 mix 或 fake 结果冒充可交付成片。
- 不通过跳阶段、换用旧资产、静默降级格式或重新生成完整原始 JSON 来绕过失败。
- 不因某个页面、镜头或 Provider 失败而删除整个 Session 或成功产物。
