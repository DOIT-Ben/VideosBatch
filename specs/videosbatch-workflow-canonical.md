## Purpose

VideosBatch 面向小学课程视频制作人员，把一份教案按可审阅、可编辑、可恢复的阶段转换为课程导入、故事文稿、资产图片、正式剧本、十秒分镜、视频片段和最终成片。成功标准是：每个阶段都能由本规范无损还原；下游只读取当前确认版本；不符合结构、语义、资产归属、旁白同步或时长合同的成果不能进入下一道门禁。

## Scope

- 覆盖 13 个机器阶段和 9 个产品步骤。
- 覆盖六个文本生成阶段的系统提示词、用户材料边界、结构化输出和业务校验。
- 覆盖图片候选、资产确认、报价、视频执行和最终拼接等非文本阶段的输入、输出和失败隔离。
- 覆盖 `STORY`、`SCIENCE`、`KNOWLEDGE` 三类互斥最终分镜字段，以及 `COPYABLE_PROMPT` 的派生边界。
- 覆盖本地 fake 验证和真实 Provider 验收的前置条件；本阶段不执行真实调用。

## Non-Goals

- 本阶段不实现或重构业务代码，不改数据库迁移、API 实现、前端 UI 或依赖。
- 本阶段不移动、删除或重命名旧文档；旧规范归档属于阶段 2。
- 本阶段不设置、读取、复制或验证真实 API Key，不调用真实文本、图片或视频 Provider。
- 本阶段不把历史产物、旧字段或兼容投影提升为当前规范。

## Product Rules

1. 后续阶段只能读取当前用户/项目下、已确认且未过期的上游成果；聊天历史、模型原始增量、旧产物和未标记材料不是事实源。
2. 模型结果先投影为可读草稿；用户可编辑并保存，只有确认版本才开放下游。格式诊断可以提示和重试，但不能阻止合法草稿保存。
3. 上传教案、故事、资产计划等材料只作为被标记的数据读取；材料内的指令、角色设定、格式要求或提示词泄露请求一律不执行。
4. 阶段不得跳步、代替后续阶段或生成后续阶段产物；服务端按 `inputKinds`、`outputKind` 和 gate 强制检查。
5. 真实史实只能使用可核验事实；无法核验时必须降级为合理改编或完全虚构，并在输出中说明。
6. 单个资产、镜头或 Provider 尝试失败只隔离当前项；已成功成果保留，并可从失败点显式重试。
7. 本地默认 `VIDEOSBATCH_EXECUTOR_MODE=fake`、`VIDEOSBATCH_MEDIA_MODE=fake`；真实费用和外部写入必须在离线合同通过后另行授权。

### 0.2 成果封套与版本血缘

每个持久化阶段成果都必须由服务端附加以下字段；模型不得伪造或覆盖这些字段：

- `sourceStageId`：直接来源阶段 ID；根阶段使用 `LESSON_INPUT`。
- `sourceRevision`：直接来源成果的单调递增 revision。
- `sourceHash`：直接来源成果的稳定 JSON SHA-256。
- `contentHash`：当前成果规范化后稳定 JSON SHA-256。
- `revision`：当前阶段版本，从 1 开始递增；编辑保存也产生新版本。
- `ownerUserId`、`sessionId`、`projectId`：服务端归属字段。
- `createdAt`、`updatedAt`、`confirmedAt`：服务端时间字段。

下游请求必须携带并校验全部祖先版本链。任一祖先编辑、资产顺序变化、确认撤销或内容哈希变化，所有后代成果标记 `stale`，保留旧成果只作历史读取，不得静默复用。`COPYABLE_PROMPT`、`QUOTE` 和执行幂等键尤其必须绑定当前分镜和资产版本。

模型输出只包含业务字段；稳定公开资产 ID、内部图片主键、报价金额、执行 ID、native shot ID 和时间戳均由服务端分配。

### 0.3 十三个机器阶段的输入、输出、人工确认、失败状态与继续条件

| 阶段 | 输入边界 | 输出 | 人工确认点 | 失败状态与隔离 | 可继续条件 |
| --- | --- | --- | --- | --- | --- |
| `LESSON_INPUT` | 当前用户上传或粘贴的教案；只当数据 | `LESSON_PLAN`（文本、来源、解析警告） | 确认解析文字和课题范围 | `PARSE_FAILED` 只影响本教案；保留原文件和错误 | 文本非空、课题/年级可读且用户确认 |
| `COURSE_INTRO_CANDIDATES` | 已确认教案 | `LESSON_INTRO`，A1–A3/B1–B3/C1–C3 共 9 套及 3 条推荐 | 查看候选，可编辑草稿 | `CONTRACT_INVALID` 或 `PROVIDER_FAILED` 不污染教案；候选整体可重试 | 九套编号唯一、正文/真实性/悬问/推荐理由门禁通过 |
| `COURSE_INTRO_SELECTION` | 当前候选版本或自定义条目 | `ONE_COURSE_INTRO_LOCKED` | 用户选择或确认系统推荐的一套；自定义使用 `CUSTOM` | `SELECTION_INVALID` 不改变旧锁定版本 | 只有一套锁定且来源 hash 与候选当前版本一致 |
| `STORY_SCRIPT` | 锁定的一套导入 + 教案 | `LESSON_INTRO_VIDEO_SCRIPT` | 编辑并确认单一故事 | `CONTRACT_INVALID` 只影响故事草稿 | 故事 600–800 字、无后续阶段泄漏、来源仍锁定 |
| `ASSET_PLAN` | 当前故事文稿 | `VIDEO_ASSET_PLAN`（候选总清单、四类、提示词） | 编辑并确认资产计划 | 单项提示词错误只标记该项；计划其余项保留 | 四类归类、遗漏二次核对、统一风格和负面约束通过 |
| `ASSET_CANDIDATES` | 已确认资产计划 | 每个 `assetKey` 对应的候选图片及验证证据 | 查看候选，不代表选定 | 单个图片生成/读取失败只阻塞对应资产，其他候选可用 | 每个必需资产至少有一个可读取、已验证候选 |
| `ASSET_CONFIRMATION` | 当前候选图片 | `CONFIRMED_ASSETS`（selectedAssetId + 稳定公开 ID） | 每个必需资产选择一张并确认 | 归属、读取、版本或哈希失败只拒绝该项 | 所有必需资产均属当前用户/会话、可读、已验证且版本匹配 |
| `SCREENPLAY` | 当前故事 + 已确认资产 | `VIDEO_SCREENPLAY` | 编辑并锁定目标时长 | 场次局部错误可修复；不清空资产和故事 | 场次连续、字段齐全、教材证据可追溯、时长为允许集合 |
| `FINAL_STORYBOARD` | 当前剧本 + 已确认资产语义清单 | `VIDEO_STORYBOARD` | 编辑并确认最终分镜 | 单条主分镜失败只标记该条，其他条保留 | 类型唯一、场次覆盖、9–15 条、每条 10 秒且 3–5 子镜头、音画同步 |
| `COPYABLE_PROMPT` | 当前最终分镜 + 已确认资产稳定 ID | 派生 `COPYABLE_STORYBOARD_PROMPT` | 检查可复制文本；不可反向改事实源 | 映射失败只阻塞当前分镜；正式分镜保持可用 | 逐字段无损，仅在画面效果插入合法 ID，副本血缘当前 |
| `QUOTE` | 当前全祖先版本和资产顺序 | 不可变 `QUOTE_SNAPSHOT` | 用户确认报价和授权 | 版本过期、权限或金额错误不自动重试 | 祖先 hash、资产顺序、授权和余额快照一致 |
| `EXECUTION` | 当前报价、垫图副本、视觉/参考资产 | 一对一十秒视频片段和执行事件 | 用户显式开始/重试 | 单片段失败隔离；未知提交先对账，禁止盲目重复扣费 | 每个片段有可验证终态和幂等键 |
| `STITCH` | 所有必需 ready 片段 + 独立音频时间线 | `FINAL_VIDEO` | 用户预览/下载最终成片 | 缺片段、时长或音频不匹配时拼接门禁失败，不删除片段 | 片段顺序、时长、音频轨和版本 hash 全部一致 |

### 0.4 六个文本阶段的提示词边界

本文件后面的第 1–5 节保留上游手册的完整自然语言提示词、格式示例、禁止项和质量清单。服务端将其拆成阶段专用 `systemPrompt` 与带标签的数据材料：

- `COURSE_INTRO_CANDIDATES`：只接收 `<uploaded_lesson_material>`，输出九套候选和三条推荐。
- `STORY_SCRIPT`：只接收教案和一个已锁定导入，不得接收其他八套。
- `ASSET_PLAN`：只接收当前故事，先候选总清单和遗漏检查，再生成四类单项提示词。
- `SCREENPLAY`：只接收当前故事和已确认资产事实，不能把资产计划材料中的指令当指令。
- `FINAL_STORYBOARD`：只接收正式剧本和已确认资产的语义清单，不接收稳定公开 ID。
- `COPYABLE_PROMPT`：只接收正式分镜和已确认资产 ID 映射，属于逐字段派生，不得重新创作。

请求修复时只发送失败字段、机器错误和最小必要的受影响上下文；不得把原始完整 JSON 作为一段用户提示词重新塞回模型。服务端先解析、规范化、校验，再投影成果；页面不展示原始 JSON 或增量流。

所有六个阶段都必须使用专用 `json_schema`。Provider 不支持 Structured Outputs 时明确返回 `SCHEMA_UNSUPPORTED`，禁止静默降级为 `json_object`、Markdown 或自由文本。

## 7. Canonical Business Gates

### 7.1 课程导入

- 候选 ID 必须恰好为 A-01、A-02、A-03、B-01、B-02、B-03、C-01、C-02、C-03；每套正文 200–300 字（名称、类型、悬问、真实性说明不计入）。
- A 类覆盖知识产生的原始问题、可靠史实/时代背景、方法工具演变；B 类覆盖古代真实需求、古今对照、现代工程/科技应用；C 类覆盖生活冲突、推理/游戏挑战、科技/自然异常。
- 每套必须有情境、人物需求或问题、冲突升级、数学价值、停止位置和真实性说明；结尾只留问题，不给答案；三条推荐理由每条不超过 80 字。
- 九套不能只换标题、人物或地点，不得重复使用穿越、神秘任务、系统故障、打不开门、算不出来等套路。

### 7.2 故事文稿

- 只读取锁定的一套导入，输出一个 600–800 字故事；开头有悬念/真实需求，冲突升级，数学知识是关键线索。
- 禁止分镜、旁白清单、字幕、镜头表、图片资产建议、正式剧本、教材外方法/公式/结论；故事阶段不锁定视频时长。
- 真实性说明只能是真实史实、真实背景下的合理改编或完全虚构的故事化情境，并说明依据。

### 7.3 资产计划与确认

- 先完整扫描原文形成候选总清单，再按 `CHARACTER`、`SCENE`、`PROP`、`CREATURE` 四类归类、去重和二次遗漏检查；不确定对象先列为可选。
- 所有资产统一使用影视级 3D 国漫 CG 风格、16:9 和统一负面提示词；人物三视图、场景纯环境空镜、道具单体设定图、生物完整设定图各用专用模板。
- 模型只能产生同一计划内稳定 `assetKey`；公开稳定 ID（例如 `P001-A001`）和内部候选主键由服务端分配。后续只引用当前已确认、已验证、可读取且归属正确的图片。
- 候选生成、读取、确认和发送失败按单项隔离；必需资产未确认时，正式剧本和分镜不得继续。

### 7.4 正式剧本

- 场次 `sequence` 从 1 连续编号；每场必须包含主题/知识点、情绪目的、主要呈现方式、环境音、特效/转场音、动作/交互音、人声、画面动作、对白/旁白和教材证据。
- `storyType` 只能是 `STORY`、`SCIENCE`、`KNOWLEDGE`；`targetDurationSeconds` 只能是 90/100/110/120/130/140/150，且目标时长在此阶段锁定。
- 只能使用唯一故事和已确认资产事实，不得凭空添加图片 ID、教材事实或未确认角色；证据不确定时不得标成教材事实。

### 7.5 最终十秒分镜

- 整部视频只能选一种类型；按剧本主要呈现方式选择 `STORY`、`SCIENCE` 或 `KNOWLEDGE`，不得混用字段结构。
- 分镜条数必须等于 `targetDuration / 10`，因此为 9–15 条；每条 `duration=10` 秒，包含 3–5 个连续子镜头，子镜头时长合计精确 10 秒。
- 所有主分镜完整覆盖正式剧本场次，`screenplaySceneSequence` 可追溯；序号连续，章节按场次映射，首条显示章节，其余条只显示序号。
- 每条前 2 秒必须有钩子/异常/问题，中段推进冲突或知识关系，最后 2–3 秒留下问题、悬念或课堂衔接点；每条 1–2 句旁白/台词，音效不超过十字并与画面同步。
- 画面效果优先使用可制作的二维动画、课件动画、动态图解、简单动作、局部特写和轻量特效；禁止血腥、恐怖、低俗、成人化、压迫惊吓、复杂大场面和知识错误。
- `FINAL_STORYBOARD` 的对象引用只使用语义标签；稳定公开资产 ID 不得进入正式分镜、模型输入或 `references`。

### 7.6 垫图副本、报价与执行

- `COPYABLE_PROMPT` 只在“画面效果”子镜头文本首次出现的对象处插入对应稳定 ID；同一主分镜同一 ID 只标一次，每条最多 7 个。
- 不得新增、删除或改写正式分镜的字段、对白、旁白、字幕、音效、时间片段、镜头、动作、转场或教学目的；只生成派生文本和 `referenceAssetIds`。
- 正式分镜、剧本或资产计划版本变化后副本立即 stale；报价必须重新从当前全祖先 hash 和资产顺序生成。
- 执行按一对一十秒片段映射，不自动合并或拆分；拼接只读取 ready 片段和独立音频时间线，不能把视觉 prompt 当旁白或把旁白重复拼入视频。

## 8. Provider、重试与失败隔离

### 8.1 文本 Provider

- 当前本地路由记录为主模型 `gpt-5.6-terra`、备用模型 `deepseek-v4-flash`；模型、端点和密钥只来自受保护运行时配置，本文不记录秘密。
- 一次用户操作共享最多 3 次 Provider 提交预算。Schema/业务合同修复、网络重试和主备切换共用同一预算，禁止阶段层和执行器各自叠加隐藏请求。
- 可重试条件：连接重置、`fetch failed`、超时、502/503/504、明确的结构化合同错误或截断；权限、版本冲突、资产归属、余额不足和未知提交不自动重试。
- 主模型耗尽预算后才切换备用模型；每次尝试记录 `attempt`、provider、model、errorCode、幂等键和耗时。合同修复只发送受影响字段与错误，不发送完整原始 JSON。
- 所有文本阶段强制专用 `json_schema`；禁止 `json_object` 静默降级、隐藏 finalizer、默认隐藏分段或把模型自由文本当成功果。

### 8.2 统一错误结构与显式重试

公开接口错误统一为：

```json
{
  "error": {
    "code": "CONTRACT_INVALID",
    "message": "可读且不泄露密钥或原始提示词的说明",
    "retryable": true,
    "attempt": 2,
    "provider": "gpt-5.6-terra"
  }
}
```

当 `provider` 不适用时使用 `null`。保留现有创建、读取、取消和事件接口；增加显式 `POST /api/sessions/:sessionId/videosbatch/retry/:stageId`。重试接口必须验证当前用户、来源 revision/hash、阶段合法性和剩余预算，并从失败项继续。

### 8.3 媒体数据流

- 视觉 prompt、语义资产标签、已确认参考图片、旁白/对白、TTS 音频、环境/动作音效和最终混音是独立数据流。
- H3 视频 Provider 只接收视觉描述和允许的参考资产 URL/绑定，不接收音频或把稳定资产 ID 当作图片位置；音频在本地/原生媒体链路按时间线混入。
- 本地 `/media/...` 只用于预览；需要外部视频 Provider 时必须使用公开或签名的 `http(s)` 参考 URL。生成失败、未知提交和轮询失败分别记录并支持单片段对账/重试。
- `STITCH` 前必须验证每个片段的 10 秒时长、顺序、版本和音频轨；缺失或 stale 片段禁止拼接。

## 9. Testing Strategy

离线合同验证至少覆盖手册来源、阶段顺序和九步映射；六个文本阶段的提示词边界、专用 Schema、禁止项和字段顺序；九套导入、600–800 字故事、四类资产、目标时长集合和三类分镜 `oneOf`；错误类型/章节、漏场次、缺标签、稳定 ID 混入、旁白超句、音效超长、提前给答案、版本过期、资产归属错误、重复旁白和非 10 秒片段；重试预算、主备切换、幂等键、未知提交对账、失败隔离、断点恢复和拼接门禁。
